# 9 项目计划

## 9.1 范围分期与优先级

优先级定义：P0 = 一期必须交付，缺失则系统无法上线；P1 = 一期尽量交付，可在资源紧张时降级；P2 = 二期/三期交付或预留。

表 9-1 一期范围分期与优先级清单

| 模块 | 功能点 | 优先级 | 所属期次 | 说明 |
| --- | --- | --- | --- | --- |
| 基础资料 | 商品档案（编码、名称、规格、单位、条码、状态） | P0 | 一期 | 全局唯一编码，停用后不可再被新单据引用 |
| 基础资料 | 商品分类维护 | P0 | 一期 | 支持多级分类，报表可按分类汇总 |
| 基础资料 | 仓库—库区—货架—库位四级树（base_location） | P0 | 一期 | 出库、盘点、调拨均以库位为最小粒度 |
| 基础资料 | 供应商 / 客户档案 | P0 | 一期 | 入库单、出库单的往来单位来源 |
| 入库 | 采购入库：创建→审核→收货→确认入库 | P0 | 一期 | 确认入库后写 wms_inventory 并生成 wms_inventory_txn 流水 |
| 入库 | 退货入库、其他入库 | P1 | 一期 | 复用入库主流程，单据类型区分 |
| 入库 | 入库单据查询与打印 | P1 | 一期 | 打印用浏览器打印模板，一期不做专用打印控件 |
| 出库 | 销售出库：创建→审核→拣货→确认出库 | P0 | 一期 | 确认出库前校验可用量并 locked_qty 预占 |
| 出库 | 领料出库、调拨出库 | P1 | 一期 | 调拨出库与调拨单联动 |
| 出库 | 库存不足拦截、FIFO 批次推荐 | P0 | 一期 | 可用量不足则拒绝过账并提示缺口数量；FIFO 按入库时间推荐库位 |
| 库存 | 库存查询（商品×库位×批次） | P0 | 一期 | 支持按商品、仓库、库位、批次多条件筛选 |
| 库存 | 库存调拨单（调出→调入） | P1 | 一期 | 调拨不改变总库存，仅改变库位分布 |
| 库存 | 库存数量调整（手工增减，需审批） | P1 | 一期 | 每次调整生成流水与操作日志 |
| 系统管理 | RBAC 角色权限（sys_role / sys_permission / sys_user_role / sys_role_permission） | P0 | 一期 | 菜单、按钮、接口三级权限 |
| 系统管理 | 数据权限（按仓库/库区限定可见范围） | P0 | 一期 | 多仓场景下仓管员只能看到本仓数据 |
| 系统管理 | 操作日志（sys_operation_log） | P0 | 一期 | 记录操作人、时间、IP、模块、动作、结果 |
| 系统管理 | 参数配置（sys_config） | P1 | 一期 | 如是否启用 FIFO、单据编号规则、预警阈值 |
| 报表 | 出入库流水报表 | P0 | 一期 | 依据 wms_inventory_txn 统计，支持导出 Excel |
| 报表 | 库存台账报表 | P0 | 一期 | 期初 + 出入库 = 期末，可按周期与商品筛选 |
| 报表 | Excel 导出 | P0 | 一期 | 导出内容与页面筛选条件一致，1 万行内可用 |
| 盘点 | 盘点单：生成→录入实盘数→差异审核→调整库存 | P1 | 二期 | 一期仅保留数据结构与入口占位 |
| 报表 | 库存周转率、呆滞料分析、收发存汇总 | P2 | 二期 | 依赖一期数据积累 |
| 库存 | 批次与保质期管理、临期预警 | P2 | 二期 | 一期 wms_inventory 已含批次字段，可直接扩展 |
| 库存 | 库存上下限预警 | P2 | 二期 | 基于 sys_config 阈值与定时任务 |
| 可视化 | 库存数据大屏 | P2 | 二期 | 使用 ECharts，非上线必需 |
| 终端 | PDA / 条码扫描作业 | P2 | 三期 | 需先完成设备兼容性验证 |
| 集成 | RFID、AGV、ERP / 电商平台对接 | P2 | 三期 | 接口协议与对方系统强相关，需单独评估 |
| 组织 | 多组织、多货主 | P2 | 三期 | 涉及数据隔离模型改造，一期不做 |

## 9.2 里程碑与排期（总周期 16 周）

表 9-2 里程碑与总体排期（16 周）

| 阶段 | 周次 | 主要工作 | 产出物 | 投入人力 |
| --- | --- | --- | --- | --- |
| 需求与详细设计 | 第 1–2 周 | 现场调研（仓库动线、单据样本、现有 Excel 台账）；确认一期范围与验收标准；绘制原型；编写需求规格说明书、数据库设计、接口清单 | 《需求规格说明书》《验收标准清单》（签字版）、原型稿、数据库设计文档、接口清单 | 项目经理 0.5 人、后端 2 人、前端 1.5 人（第 2 周起）、测试 0.5 人（参与评审） |

| 核心业务开发（入库/出库/库存） | 第 3–9 周 | 完成基础资料 CRUD、入库全流程、出库全流程、库存查询与调拨；实现可用量预占 + version 乐观锁 + requestId 幂等过账 | 一期核心模块可运行版本、单元测试、后端接口文档 | 后端 2 人、前端 1.5 人（第 5 周起联调） |
| 前端开发与联调 | 第 5–12 周 | 与后端并行：第 5–7 周完成基础资料、入库页面；第 8–10 周完成出库、库存、调拨页面；第 10–12 周接入 ECharts 报表页面；按接口文档 mock 数据先行开发，接口就绪即联调 | 前端页面、联调记录、前后端接口变更记录 | 前端 1.5 人、后端 2 人（每周固定联调时间） |
| 盘点与报表 | 第 10–12 周 | 出入库流水、库存台账报表与 Excel 导出；盘点单流程（二期功能，一期如资源允许则一并开发并纳入 UAT） | 报表模块、导出功能、盘点单功能（可选） | 后端 2 人、前端 1.5 人 |
| 测试与性能优化 | 第 11–14 周 | 第 4 周起测试介入编写用例（提前介入）；第 6 周起接口自动化回归；第 11–13 周系统测试与 UAT；第 13–14 周性能压测（200 并发）与调优、安全自查 | 测试用例集、缺陷清单与回归报告、性能测试报告、安全自查报告 | 测试 0.5 人（第 4 周起）、后端 2 人、前端 1.5 人 |
| 数据迁移与试运行 | 第 13–15 周 | 收集并清洗客户 Excel 台账；按模板导入商品、往来单位、库位、期初库存；生成校验报告并处理失败行；期初全盘校准；双轨运行与用户培训 | 迁移脚本与导入批次记录、校验报告、期初库存确认单、试运行记录 | 实施 0.5 人、后端 1 人、客户关键用户 |
| 上线与培训 | 第 15–16 周 | 上线前检查清单核对、数据备份、正式切换；分角色培训与考核；切换后 3 天现场支持；交付文档与源码 | 上线检查清单、培训签到与考核记录、验收报告、完整交付物包 | 实施 0.5 人、测试 0.5 人、后端 1 人、前端 0.5 人 |

说明：总周期 16 周为连续工作日口径；第 4 周测试提前介入编写用例、第 5 周前端与后端并行联调、第 3 周数据库先行，均为压缩总工期的关键安排。第 3–9 周为核心业务开发的关键路径，任何变更若影响该区间需立即上报项目经理。

### 10.2.3 数据校验规则

1. 编码唯一：商品编码、供应商/客户编码、库位编码在模板内不得重复，且不得与系统现有数据冲突。
2. 必填完整：必填列为空的行直接失败，不导入。
3. 格式与数值：数量列为数值型且 ≥ 0；单位、分类必须在系统字典内；日期格式统一为 yyyy-MM-dd。
4. 关联存在：期初库存的库位编码必须已存在于 base_location；商品编码必须已成功导入 base_goods。
5. 逻辑一致：同一商品同一库位同一批次在模板中只允许出现一行，重复行合并前需人工确认。
6. 上限校验：单次导入行数上限按 1 万行控制，超出则拆分批次。

### 10.2.4 导入方式

1. 系统管理模块提供"数据导入"功能，按数据类型（商品 / 供应商 / 客户 / 库位 / 期初库存）分别提供模板下载入口。
2. 上传后先执行"预校验"，不写库，仅生成校验报告：成功行数、失败行数、失败原因（行号 + 列名 + 原因）。
3. 失败行支持"下载失败明细"（Excel），客户在本地修正后重新上传，只导入修正后的行。
4. 校验通过后由实施人员点击"确认导入"，系统按导入批次号写库，并记录导入人、时间、批次号、行数。
5. 每个导入批次可在"导入批次记录"中查询与撤销（撤销仅在该批次数据未被单据引用前有效）。

### 10.2.5 期初库存确认方式

1. 期初库存导入完成后，系统生成该批次的期初流水（wms_inventory_txn，类型为"期初"），数量与 wms_inventory 的 quantity 一致。
2. 在正式上线前安排一次全盘校准：以系统库存清单为底稿打印盘点表，仓管员实地清点并回填实盘数。
3. 实盘数与系统数不一致的，填写差异原因（漏记、串位、损耗、录错），经仓储主管签字确认后，在系统中做一次库存数量调整并生成调整流水（不直接改数据库）。
4. 校准后再次核对：期初流水 + 调整流水 = 当前 wms_inventory 数量，账实一致后由客户签署《期初库存确认单》，作为后续库存责任的起点。
5. 确认单签署后，期初数据冻结，任何进一步调整必须走库存调整流程并留痕。

### 10.2.6 回退方案

1. 每次导入前对数据库做一次完整备份（含 wms_inventory、wms_inventory_txn 及相关基础表），备份文件与生产服务器分离存放。
2. 导入按批次号执行，撤销时按批次号逆向处理：删除该批次新增的期初流水并回滚对应库存数量；已被业务单据引用的批次不允许撤销，需走人工数据修正流程。
3. 若导入后出现大面积数据错误（如单位换算整体错误），回退至导入前备份点，重新整理 Excel 后再次导入。
4. 回退操作仅由实施人员在项目经理确认后执行，并记录操作日志。

### 10.3.2 上线切换步骤

1. **切换前检查清单（切换前 3 个工作日完成）**：云服务器与域名可用、HTTPS 证书正常；数据库脚本在生产环境执行完毕；生产环境功能冒烟测试通过；备份任务已执行且备份可还原验证通过；期初库存已全盘校准并签署确认单；用户账号与角色权限配置完成；打印机、条码枪等外设已实测；回退脚本与回退负责人已明确；客户方业务与 IT 对接人名单及联系方式已确认。
2. **切换前数据冻结（切换前 1 个工作日）**：停止新单据在旧 Excel 台账中的录入；对生产数据库做一次完整备份并留存备份路径与校验值。
3. **双轨运行（1–2 周）**：系统与原有 Excel 台账同时记录；每日由仓管员核对当日出入库数量，填写《双轨核对表》；出现差异当日查明原因并在系统中修正；连续 5 个工作日差异为 0 后进入正式切换。
4. **正式切换（业务低峰期，建议周末或非结算日）**：确认无在途单据；执行最终数据备份；关闭 Excel 台账录入入口并作为历史归档；系统开放正式使用；切换过程填写《上线切换记录表》，记录开始/结束时间与操作人。
5. **切换后现场支持（切换后 3 个工作日）**：实施人员驻场，处理操作疑问与数据异常；每日下班前汇总问题清单并当日闭环；对高频问题补充说明并更新操作手册。
6. **切换后回访（切换后 2 周）**：远程回访运行情况，检查报表数据与实物一致性，形成《上线运行报告》。
